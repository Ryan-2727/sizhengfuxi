# 题库逐章精选与内容质量复核设计

日期：2026-08-12

## 目标

在不修改任何原始 `questions.payload` 的前提下，对五门课程的现有题库增加一层可追溯的章节精选与质量门槛：

1. 隔离高风险、重复、答案结构异常或章节无法可靠定位的题目。
2. 每个教材章节目标精选 10 道选择题和 2 道大题。
3. 精选题必须具有可靠来源、明确章节、完整答案和达到门槛的解析。
4. 对解析、得分点、关键词和章节归类进行自动一致性检查。
5. 数量不足时输出真实缺口，不用低质量题补齐数量。

## 约束

- 原始题干、答案、解析和题目顺序保持不变。
- 展示修正继续写入 `question_revisions`，发布、来源和精选状态继续写入 `question_quality`。
- “章节精选”表示通过本项目的质量筛选，不等同于人工逐字核验。
- 只有教材、教师答案或权威公开资料确实提供证据时，才保留对应的来源核验标签。
- 自动章节规则只能产生 `candidate`；只有现有教材页码证据、已审教师分章资料或明确的人工覆盖规则可以产生 `verified`。
- 不把完整题库、答案或解析重新放入 Git 或前端静态产物。
- Supabase RLS、会员校验、按课程懒加载和 IndexedDB 缓存机制保持不变。

## 方案

采用“原始题库 + 非破坏性修订 + 精选元数据”方案。

不建立第二套题库表，也不复制题目正文。`question_quality` 增加少量精选字段，脚本从现有全量编辑清单中确定每章候选、排序和缺口。这样能够沿用现有 RLS、缓存版本和题目稳定 ID，并保证任何显示变化仍可追溯到原始记录。

### 精选元数据

为 `question_quality` 增加：

- `curation_status`：`standard` 或 `chapter_core`。
- `curation_rank`：题目在同课程、同章节、同题型精选集中的顺序。
- `curation_reason`：不包含题目正文的简短入选依据。
- `curation_version`：生成规则版本，用于审计和后续重建。
- `curated_at`：首次写入当前精选状态的时间。

字段由使用 `SUPABASE_SERVICE_ROLE_KEY` 的本地同步脚本写入。普通用户只有在有效会员 RLS 通过后才能读取已发布题目的质量元数据，不能修改精选状态。

## 发布门槛

以下情况不得发布：

- 答案字母不存在于选项或单选、多选类型冲突。
- 高风险限定词缺少教材、教师答案或权威资料证据。
- 已确认重复题且存在保留的主版本。
- 跨课程内容、OCR 异常或字段错位尚未完成复核。
- 无法可靠定位章节并且没有人工覆盖依据。

这些题目继续使用 `hidden_duplicate` 或 `hidden_review`，由数据库 RLS 阻止直接读取，而不物理删除。

## 精选资格

题目必须同时满足以下条件才可以进入 `chapter_core`：

1. `publication_status = published`。
2. 章节状态为 `verified`，且章节 ID 属于对应课程教材目录。
3. `review_status = source_verified`。
4. `verification_status` 为 `teacher-key-verified`、`textbook-law-verified` 或 `authoritative-source-verified`。
5. 不含高风险待核验、重复、跨课程、章节待归类、无效答案或格式异常等阻断问题。
6. 原始 payload 哈希与既有不可变基线一致。

选择题还必须满足：

- 正确答案存在且与选项完整对应。
- 单选、多选类型与答案数量一致。
- 有至少两层与本题直接相关的解释，并明确定位正确选项。
- 解析包含题干限定、排除思路或记忆定位中的至少一项，不能只写答案字母。

大题还必须满足：

- 标准答案直接回答题目，不能只告诉用户“从哪些方面作答”。
- 至少 3 个可在标准答案中逐项追溯的得分点。
- 至少 2 个关键词、1 条常见失分提示和 4 个解析句段。
- 答案、解析、得分点和关键词分别展示，不互相替代。

## 逐章选择

每章按题型独立排序，目标为 10 道选择题和 2 道大题。排序采用稳定、可重复的评分：

1. 教材页码或教师分章答案证据优先。
2. 章节证据置信度高者优先。
3. 原解析能解释正确项并辨析干扰项者优先。
4. 大题答案层次、得分点和关键词更完整者优先。
5. 避免规范化题干相同或高度相似的题目重复入选。
6. 分数相同时按原课程、题型和题目顺序确定结果。

如果合格题不足，报告记录 `choice_gap` 或 `essay_gap`。缺口不会自动用 `source-backed`、`candidate` 或待核验题填补。

## 解析处理

精选题优先使用原题已有的具体解析。只有在不新增事实判断的情况下，修订层才补充以下结构信息：

- 选择题：题干限定、正确项定位、排除顺序和记忆关键词。
- 大题：设问定位、答案组织顺序、得分点映射、关键词和常见失分。

自动补充不得声称某个错误项对应具体历史时期、理论或制度，除非原解析或核验证据已经明确支持该判断。无法可靠补充的题目不进入精选集。

## 章节归类复核

章节复核分为三层：

- `verified`：教材同页证据、已审教师分章资料、题目自身的已核验章节字段或明确人工覆盖。
- `candidate`：加权关键词和语义规则给出的候选章节。
- `unclassified`：无法可靠定位。

精选集只接受 `verified`。脚本单独输出 `candidate` 和 `unclassified` 队列，包含题目引用、候选章节、置信度、命中依据和风险类型，供后续人工复核。

## 输出物

- `data/question-curation-manifest.json`：可提交的轻量清单，只含题目引用、章节、题型、精选顺序、核验状态和规则版本，不含题干、答案或解析。
- `data/question-bank-source/question-curation-report.json`：本地详细报告，位于已忽略目录，可包含审计所需正文。
- `docs/question-curation-coverage-2026-08-12.md`：五门课逐章覆盖率、缺口和待人工复核总量。
- `scripts/audit-question-curation.js`：生成上述清单与报告。
- `scripts/verify-question-curation.js`：验证精选资格、数量、稳定性、重复和不可变 payload。

## 前端行为

- 题集筛选区增加“章节精选”。
- 精选题显示克制的“章节精选”标签。
- 来源核验标签继续独立显示，避免把“精选”误解为“教材原题”或“人工逐字核验”。
- 选择精选筛选时仍可叠加章节、题源、搜索、错题和收藏相关现有流程。
- 精选字段随课程题库一起懒加载并写入当前账号的 IndexedDB；目录哈希纳入精选元数据，精选变化后对应课程缓存自动失效。

## 数据流

1. 本地审计脚本读取被忽略的题库源文件和现有教材证据。
2. 全量编辑清单先执行答案、章节、风险和重复题检查。
3. 精选模块只从满足资格的已发布题中逐章选择。
4. 默认命令只生成报告，不连接或写入 Supabase。
5. 管理员显式执行 `questions:sync-quality -- --apply` 后，服务角色写入修订和精选元数据。
6. 同步脚本重算 `question_bank_catalog.content_hash`。
7. 有效会员下次打开对应课程时，因哈希变化重新下载一次并写入按账号隔离的缓存。

## 验证

自动验证至少覆盖：

- 原始题库 payload 数量和 SHA-256 全部不变。
- 所有未隔离的高风险题都有可靠来源证据。
- 精选题均已发布、章节已核验、来源已核验且答案结构有效。
- 每个章节最多 10 道精选选择题和 2 道精选大题，排序无重复且可重复生成。
- 未达目标的章节在覆盖报告中准确列出缺口。
- 精选大题得分点都能在标准答案中找到，选择题解析包含正确选项定位。
- migration 保持 RLS 和只读权限，普通用户不能修改精选状态。
- 目录哈希包含精选字段，数据库同步后缓存会失效。
- 题集筛选、答案解析、错题本、收藏、搜索、随机题和背诵功能不回归。
- `npm run content:qa`、现有安全验证和 `npm run build` 通过。
- `dist/` 不含完整题库源文件、题目清单正文或 `service_role` 密钥。

## 部署顺序

1. 在 Supabase SQL Editor 执行新增 migration。
2. 本地运行题库审计与精选验证。
3. 使用本地服务角色密钥执行质量同步 `--apply`。
4. 运行数据库校验并确认目录哈希已更新。
5. 部署前端到 Cloudflare Pages。

在 migration 和同步完成前不部署依赖新字段的前端，避免生产读取字段不存在。

## 不做

- 不删除或覆盖原题库。
- 不把自动规则结果标成“人工核验”。
- 不为达到数量目标生成新题或重复题。
- 不引入新的管理后台、登录流程或题库表。
- 不修改课程知识正文和教材引文。
